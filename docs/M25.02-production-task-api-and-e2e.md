# M25.02 — Production Task API and E2E

## Scope
- Tenant-scoped durable task records in `ce_production_tasks`.
- Authenticated create/read/transition API under `/api/production/tasks`.
- Idempotent create using the required `Idempotency-Key` header.
- Optimistic concurrency using a monotonically increasing version.
- State machine and evidence-gated success are enforced by `production-task-harness`.
- E2E runner checks create, retry, readback, transition flow, evidence gate, final persistence and stale-write rejection.

## Endpoints
- `POST /api/production/tasks`: create with `title`, `objective`, `acceptanceCriteria`.
- `GET /api/production/tasks?id=<uuid>`: read only within the resolved tenant.
- `PATCH /api/production/tasks`: transition using `id`, `version`, and `transition`.

Every request requires the existing Core Engine bearer API-key authentication. Tenant identity is resolved server-side; client-supplied tenant identifiers are ignored. The Supabase service-role key remains server-only. The database table has RLS enabled and no client-facing policies; access is mediated by the server route.

## Run E2E
Set `CORE_ENGINE_API_KEY` in a trusted shell and run:
```sh
CORE_ENGINE_BASE_URL=https://core-engine-34uu.onrender.com node scripts/production-task-e2e.mjs
```
Do not place production secrets in repository files, screenshots, shell history shared with others, or logs.

## Completion gate
M25.02 is complete only after the migration is applied, the CI gate reports all checks passed, the production E2E script exits zero, and its returned task ID/state/version are retained as evidence. A Render `live` deployment alone is not sufficient.
